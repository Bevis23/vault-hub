# 术语表（中英对照）

> 这份表是**中英双语（i18n）的地基**：先把中文说法统一、英文译法定死，
> 之后翻译才不会前后不一致。每次新增 UI 文案，都按这里的表来。

---

## 一、先解决三个「同一个东西好几种叫法」的问题

代码里现在是分裂的，必须统一，否则翻译会翻出三种英文：

| 现在的混乱 | 定死后 | 说明 |
| --- | --- | --- |
| **外部库**（38 处）/ **其他库**（8 处）/ README 里的「别的库」 | UI 统一 **其他库**；**代码注释继续用"外部库"** | 注释是给开发者的内部术语，不用改；只有显示给用户的那十几处要统一 |
| **工作台**（插件本体）/ **工作面板**（打开模式）/ **工作区**（UI 区域） | 中文不动，**英文必须分开**：Workbench / **Panel** / Workspace | 「工作面板」翻成 workspace 会和整个插件的 Workbench 撞车 |
| **库导航**（侧栏）/ **库管理**（设置子页） | 中文不动，英文分开：**Vaults** / **Manage vaults** | 都翻成 Vaults 会让设置页看不出区别 |

## 三、文案准则：中文也要瘦身

**原则：把用户当聪明人。** UI 上只留一句能 get 到意思的短句，详细解释放「使用说明」或 hover `title`。

| 类型 | 上限 |
| --- | --- |
| 菜单项 | ≤ 12 字 |
| 提示 | ≤ 20 字 |
| 禁用原因 | 一句话说清「**怎么修**」，而不是「为什么不行」 |
| 长解释 | 移进使用说明子页 / `title` |

### 对照示例

| 现在 | 精简后 | 英文 |
| --- | --- | --- |
| 外部库：请到左边库导航右键这个库 → 切换到此库，就能做这些了 | **切换到此库后可操作** | Switch to this vault to use this |
| MVP 阶段仅「新建笔记」会写入操作日志；后续批量整理上线后… | **当前仅记录新建笔记** | Logs new notes only for now |
| 侧栏提示「右键库 → 切换到此库」 | **右键可切换** | Right-click to switch |
| 删除走 Obsidian 自己的删除通道，按你在设置里选的回收站策略走… | **经 Obsidian 删除，可回收** | Deleted via Obsidian — recoverable |

## 四、执行 i18n 时的顺序（不能反）

1. **术语表定稿**（本文件，人工拍板）
2. **字典收口 + 中文瘦身**（18 个片段 → 一个 `src/05-i18n.js`）—— 搬的时候顺手精简
3. **批量翻译**（带术语表 + "这是 UI 文案，不是文档，要短"）
4. **回译抽检**（随机 30 条翻回中文比对）
5. **实机检查**（英文通常比中文长 30–60%，看菜单会不会溢出）

**回退机制**：英文缺失时自动显示中文 —— 保证永远不会出现半中半英的界面。
**构建校验**：`build.js` 检查每个 key 是否 zh / en 都有，缺了直接报错。
